# MOONCRATER-001 — Everything Into Something

Research specimen, not a live fundraiser, investment product, payment rail or ledger. No real participant data. Main remains unchanged.

## Admission and outcome

An offer record carries a source ref, owner consent, rights scope, delivery evidence, demand evidence, delivery deadline, cost, approved payment route, and proposed beneficiary allocation. All gates remain HOLD until locally checked. Offer -> accepted scope -> delivery -> independent witness -> provider-settled proceeds -> consented allocation -> transfer -> receiving-side confirmation. Work and money remain separate.

Keep currencies separate; record gross, fees, refunds, net, paid date and actual recipient settlement separately. Record conversion only against actual FX receipts. Duplicate external transaction evidence must never be credited twice; the toy code only checks event IDs and is not production reconciliation. No external data is verified by the fixture.

## Counterpressure

Run `node labs/mooncrater-001/pressure.mjs` (no dependencies). Synthetic checks cover removal of each readiness gate, refusal of duplicate event IDs, unbacked disbursement and cross-campaign spending, and conservation. Code-mode evaluation passed the 13 first checks; Node/CI and real-world validation not run. Missing customer, loss of largest donor, no network, no available legal payment route, fraud, duplicate external receipts and refund/dispute races remain required follow-up cases.

## Campaign protocol

Start with a private need record and separate beneficiary-controlled authorization. Confirm exact need, documentation, deadline, lawful recipient, and payment route; test extension/staged settlement independently of fundraising. Offer conditional participation before verification, never solicit funds using unverified assertions. Do not publish identity, contact, property or household records. Maintain local authority, minimal export, separate gifts from sales and investment, and no promised return. No real-world campaign data in this public branch.

Compare with a direct-giving-only baseline on actual net received, recipient-confirmed amount, participant hours, costs and failures. Stop expanding software if one direct route works better. Null result is a valid result.

First field milestone: a single independently witnessed, consented external exchange and a distinct, reconciled receipt. Until then: zero verified funds in this experiment.
