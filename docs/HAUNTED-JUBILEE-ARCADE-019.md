# PENNY-019 — The Haunted Jubilee Arcade

**Status:** runnable offline *synthetic* two-box specimen, not a commissioned arcade, treasury node, station product, real camera, print service, verified identity system, or live cryptocurrency/payment apparatus.

**Premise:** haunted D&D / Jubilee / Pokemon Go / photobooth arcade and mechanical fortune teller. One physical-turn-shaped action proposes useful work, six haunted metadata frames develop around an imported image, a human chooses, an operator approves a printable text card, and a separate locally sovereign box receives the MAIL parcel as **HOLD**. A recipient can privately reinterpret the card without changing parent evidence.

## Try it

Requires Node 20+; no install, camera, printer, wallet, device or network access required:

~~~sh
npm run penny019:test
npm run penny019:demo
npm test
~~~

Or call node --test test/haunted-jubilee-arcade-019.test.mjs and node src/haunted-jubilee-arcade-demo-019.mjs. The demo embeds a tiny synthetic PNG, and all human approvals in it are simulated by fixed operators. Its text output is an ASCII-printable postcard projection. It does not generate real image pixels or print actual paper.

## Exactly what executes

1. A **simulated edge is consumed** once with deviceId, sessionId, sequence, direction, ticks=1 and no authority. An invalid work payload still spends the accepted simulated edge. This in-memory test is NOT the crash-safe POSIX/ESP32 gate owned by CRANKNODE-003.
2. A **HELD offer candidate** contains a bounded work invitation, voluntary alias, permissions, and SHA-256 of exact imported local photo bytes. The program never captures a shutter event. PNG/JPEG magic is not image decoding, authenticity, or consent proof. Source bytes are never persisted to journal/card.
3. Six deterministic **metadata** lens proposals point to the same immutable source image digest; there is no model-driven pixel production. A human chooses KEEP, COMPOST, or HAUNT. COMPOST prevents card publication.
4. A **human-approved print projection** requires print permission, chooser, and approver. The card truthfully records printedPhysically=false and the phrase NOT PHYSICALLY PRINTED. No printer is contacted.
5. Braided **NOW / MAIL / HEIR**: a human prepares a parcel for another named box. The receiver verifies internally hash-linked evidence and records RECEIVED_FOR_LOCAL_HUMAN_REVIEW_HELD, not global canon, delivery, signed reLATTE acceptance, station approval, or treasury backing.
6. **Receiver freedom:** an independent recipient may add one private HEIR interpretation with retained ancestry and no inherited public rights.
7. **Coin lane:** an unsigned claim of pennies becomes UNVERIFIED_COIN_REPORT_HELD. Coin backing verified = 0 and active PENNY units = 0, regardless of report count. The simulation does not import PENNY-014 custody signatures or verify coins.

## Hostile and privacy limitations

Journal hashes detect change relative to an *independently trusted known head*. Because this specimen lacks signatures, an adversary can forge a new internally consistent history and head. Before any real handoff, sender authenticity, current owner consent, withdrawal freshness, image rights (including third parties/minors), exact bytes, and recipient admission must be independently established.

The offline receiver cannot discover a withdrawal made *after* the sender prepared a parcel unless a trusted channel supplies updated facts. Previous paper copies cannot be unprinted. Exported journals contain contributor offer and alias text; do not put real personal/donor data or private photos in public repository fixtures. The model is in-memory and **not crash durable**. Real-world serial gates and custody must retain their own authoritative native implementations.

Tests cover edge reuse even after failed work, semantic smuggling, image byte binding, six independent metadata frames, COMPOST, missing print/mail rights, verified printable projection without claiming paper, MAIL/HOLD, duplicates, wrong destination, modified card and journal, pre-mail withdrawal, penny reports that never issue, and independent HEIR that does not mutate source.

## Physical cabinet and later slices

Intended physical shell: hand crank, mechanical fortune-teller dial, LED camera flash theater, manual coin slot, letterbox, visible human approval controls, and optional paper printer. The flash is theatrical LED illumination or a spring/mechanical POP **only**—no flash powder, explosive bulbs, mains-voltage tinkering, or firing vintage flashbulbs.

- **019a:** Native CRANKNODE-003 integration with truly durable one-edge gate and inspected camera-import/shutter adapter, while preserving independent owner approvals.
- **019b:** Device-supplied printer status and separately witnessed exact physical paper handoff (do not let print projection stand for paper).
- **019c:** Signed reLATTE transport and true sovereign recipient HOLD; permission freshness, revocation, duplicated edge and key recovery.
- **019d:** Partner-approved Kinship Living Gift interface; never auto-air, donor-profile, or infer donations from arcade play.
- **019e:** Independent physical custody audit, funds/consumer protection review, signed PENNY-014 work and deposit roles, and redemption policy before any financial issuance.

A passing simulation is a bounded design test, not evidence that a physical cabinet, camera, printer, penny, station, human witness, or blockchain was contacted.
